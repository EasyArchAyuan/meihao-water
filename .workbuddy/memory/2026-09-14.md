## ⚠️ 事故：`.git` 目录丢失与恢复

**起因**：推送时 `git push` 报 `cannot spawn sh`（沙箱 Bash 的 coreutils/PATH 损坏，默认凭据助手链走不通）。随后在坏 PATH 下执行 `git stash push -u` + `git rebase` → `fatal: Unable to create '.git/index.lock': No such file or directory` → `.git` 整体消失，`git status` 报 `not a git repository`。

**源码无丢失**：先整目录备份到 `C:\Users\shang\mhsy-backup-20260914`（src/content/scripts/cloudbase/cloudfunctions/.github/docs/infra/public）。此前 3 个本地提交 `3a0fcb9`/`12d55df`/`85870d1` 的 **commit 对象随 `.git` 一起丢失**，但工作区文件全在。

**恢复过程**（关键：只重置索引、保留工作区）
```
git init -b main
git remote add origin https://github.com/EasyArchAyuan/meihao-water.git
git fetch origin main
git update-ref refs/heads/main FETCH_HEAD
git reset --mixed main
```
- 期间被 WorkBuddy 频率限制（429，08:00 重置）打断一次，续跑后成功。
- 恢复后 `HEAD` = `origin/main` = `22e3c14 chore(release): 1.1.3 [skip ci]`。

**恢复后发现的降级风险（重要）**：工作区 `package.json` 版本是 `1.1.2`、`CHANGELOG.md` 少 6 行 —— 因为 CI 的 semantic-release commit 只推到了远程，本地从未同步。**直接 `git add .` 提交会把版本降级回 1.1.2**。处置：
```
git checkout HEAD -- package.json package-lock.json CHANGELOG.md   # 拉回远程基线
# 然后在 package.json 里重新只加 4 个 scripts
```
（4 个 scripts：`verify:ssg` / `check:content` / `sync:content` / `notify:build`）

**环境坑记录**：沙箱 Bash 缺全部 coreutils（`ls/head/tail/wc/rm/dirname`），`rm` 被 safe-bin shim 拦截 → 清理临时文件改用 `git clean -f -- <显式路径>`；PowerShell 工具不回显 stdout。**以后不要在坏 PATH 下跑 stash/rebase。**
