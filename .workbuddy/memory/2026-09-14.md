## 🐛 修复：文章取数「短路降级」导致新文章静默不上线

**发现**：上线后复查 `src/lib/content.ts` 取数逻辑，原实现是
```ts
const raw = (await fetchFromApi()) ?? loadSnapshot() ?? loadMarkdown();
```
`??` 是**短路**：只要 `content/snapshot.json` 存在（当前有 1 篇），`content/news/*.md` **永远不会被读取**。
而每周自动化（id `74ec7dd5…`）的发布动作正是「写 `content/news/<slug>.md` 后提交」→ **门禁会过、CI 会绿、但新文章根本不进产物**，而且不报错。这是静默失败，最危险的一类。

**修法**：加 `mergeSources(...)`，改为**合并去重**，同 slug 后者覆盖前者，顺序 = Markdown（低）→ 快照（中）→ 接口（高）：
```ts
const fromApi = (await fetchFromApi()) ?? [];
const raw = mergeSources(loadMarkdown(), loadSnapshot() ?? [], fromApi);
```
保留「8 秒超时降级」，绝不让 CI 卡死。

**验证（端到端，不只是跑通构建）**
1. 构建日志 stderr 从只打「使用本地快照」变为**同时**打「使用 Markdown 兜底：N 篇」+「使用本地快照：1 篇」。
2. 临时插入 `content/news/merge-probe-temp.md` → 构建 → `out/news/merge-probe-temp/index.html` **存在**（`PROBE_PAGE_EXISTS=yes`），原文章页仍在。
3. 删除探针（`git clean -f --` + 清 `out/` 对应目录），恢复干净工作区。
