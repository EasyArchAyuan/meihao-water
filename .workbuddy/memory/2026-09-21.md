### 5. ⚠️ 重大事故：`git rm` 导致整个 `src/` 从磁盘消失

**经过**：用 Bash 跑 `git rm -q` 删除 4 个废弃组件后，`git status` 显示全部 50 个 src 文件为
deleted，随后 `Test-Path src` = False —— **`src/` 整个目录消失**（本轮所有改动随之丢失）。

**恢复**：`.git` 索引与 HEAD 完好（`git ls-files -- src` = 50），执行
`git restore --staged -- src && git checkout -- src` 后 `worktree missing count = 0`，完整还原。
恢复前已 `Copy-Item` 备份 `.git`（12.4 MB / 59 文件）到 `%TEMP%`。

**根因**（同日由第二轮构建卡死暴露）：WorkBuddy 的 safe-delete 拦截层在**中文路径**下失败 ——
`[safe-delete][SAFE_DELETE_FAIL_CLOSED] {"target":".next","reason":"trash-failed","detail":"OK C:\...\缇庡ソ姘翠笟瀹樼綉2.0\.next"}`
（`缇庡ソ姘翠笟瀹樼綉2.0` 是「美好水业官网2.0」的 UTF-8 字节被按 GBK 解读）。
表现为：**删除报错，但文件实际被移入回收站（对外看就是"消失"）**；作用在目录上时可能殃及上级/整棵子树。

**规避（已写入 MEMORY.md §3）**：
- 一律不用 `rm` / `git rm` / `git clean` / `Remove-Item` 删除本项目内文件；
  改用 **`Move-Item` 移出项目**（同盘重命名，不触发拦截层）。
- `next build` 收尾会清理 `.next`/`out` → 同样卡死（实测挂起 10 分钟、`BUILD_EXIT=127`）。
  **构建前先 `Move-Item` 把 `.next`/`out` 移到 `C:\Users\shang\WorkBuddy\.build-trash-<date>`**，
  之后构建 27 秒完成。
