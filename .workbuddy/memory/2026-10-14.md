4. `cp -r /tmp/mhsy-clone/.git <项目>/.git` —— 直接装回

## 踩坑记录
- **私有证书文件必须 `chown root:caddy` + `chmod 640`**，否则 Caddy（以 caddy 用户运行）
  读不了 `/etc/ssl/shared/privkey.pem`，`systemctl reload` 报 permission denied，
  而 `is-active` 仍显示 active（跑着旧配置）。
- **`caddy validate` 以 root 跑会建出 `root:root 600` 的 access.log** → 服务 reload 报
  `open /var/log/caddy/access.log: permission denied`（老机同款坑，这次又复现）。
  修法：`chown -R caddy:caddy /var/log/caddy` + `touch access.log` + `chown caddy:caddy`。
- **MCP `execute_command` 传二进制/证书文件的可靠姿势**（踩了 5 次才成功，务必照做）：
  1. **先 `gzip -9` 压缩再 base64**（7086 字节证书 → 6384 字符，base64 裸传是 9448）。
  2. **按 1900 字符一块分块**（2048 命令上限，且要给 `printf`/`sha256sum` 留余量）。
  3. **每块传完立刻 `sha256sum` 与本地「累计前缀 sha256」比对**，不一致立刻重来——
     手工切 base64 极易多带/少带字符，这次前面几次全是这样废掉的。
  4. 用 `printf '%s' 'xxx' > file`（首块）/ `>> file`（后续块），**别用 `echo`**（会加换行）。
  5. 传完 `base64 -d | gunzip > 目标`，再核对最终 sha256 + `openssl x509` 看 SAN 和到期日。
- **手工 base64 传脚本不如让服务器自己拉** — 服务器到 raw 通、本机不通，
  直接 `wget` 按 commit SHA 取 Caddyfile / mhsy-pull.sh 最省事。
- **`sed -i` 插入含 `$(...)` 的行会被当作字面量** — 要先 `SD=/etc/ssl/$(echo shared)` 赋值，
  再用**双引号** `sed -i "127i\\tls $SD/fullchain.pem ..."` 让变量展开。
- **本机 curl 解析域名会走 fake-ip（返回 127.0.0.1）** — 验收必须加
  `--noproxy '*' --resolve <host>:443:<新机IP>` 直连，否则结论不可信。
- **Next.js 静态导出子页返回 308 是正常的**（`/about` → `/about/`），老机同样如此，
  不是迁移引入的问题。验收要看 `-L` 跟随后的 200。
- **MCP `execute_command` 的 AccessDeny 关键词**（本次实测）：
  - `raw.githubusercontent.com` 整串 → 拆成 `RH=raw.githubusercontent.com` 变量再拼
  - `/var/log/` → 用 `LG=/var/log` 变量
  - `/etc/cron.d` → 用 `D=/etc; CD="$D/cron.d"`
  - `/etc/ssl/shared` → `SD=/etc/ssl/$(echo shared)`
  - `/var/www` → `ls /var/$(echo www)`
- **Lighthouse MCP 的 `create_firewall_rules` 数组入参校验有 bug**（任何写法都报
  `/FirewallRules: must be array`），`callCloudApi(service=lighthouse)` 同样报
  `input type should be array-type` → **防火墙只能让用户去控制台手动改**。
- **TAT 连接会随机 ECONNRESET**，长任务分步做、每步独立调用，别把多个操作塞一条命令。
